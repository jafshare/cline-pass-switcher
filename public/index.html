本地代理 + 观测面板 —— 枚举订阅模型背后的上游，多上游按优先级自动故障转移，支持精确钉住 / 优先回退 / 排除上游 / 成本·首字·吞吐排序
尚未配置上游 API Key：在下方「账号管理」添加你的 Cline Pass 账号（sk_ 开头的 key）并保存即可开始使用；也可通过 config.json 的 accounts 或环境变量 CLINE_PASS_KEY 提供。
这个工具是干什么的？你订阅了 Cline Pass 之后，同一个模型背后其实有好几家公司在提供算力（这些话里叫「上游」）。 Cline 默认自己分配，你既不知道这次是谁在服务，也没法指定。这个工具就是让你能看见、并且指定。

① 能看见：每条请求都会记录本次到底是哪家上游在服务你，在「请求历史」里能看到。
② 能指定：点「优先」把想要的上游加进候选名单，再选「严格钉住」就能锁定，详见下方「订阅模型」区的说明。
③ 探测：「探测」按钮会问 Cline「这个模型有哪些上游可用」，不需要你真的花钱跑一次完整对话。
④ 自动换人：如果第一个上游报错、超时或网络不通，会自动换下一个重试；全部失败才会把错误返回给你。 流式输出在还没有吐出任何内容之前也能换人，一旦开始输出就没法再换。

订阅模型（cline-pass/*）

这个表格在管什么？同一个模型，Cline 背后其实有好几家服务商（叫「上游」）在提供。这里就是让你决定：这次请求尽量交给谁、哪些绝对不用。
① 先选上游（点「优先」）：点一下某个上游的「优先」，它就加入候选名单，左边的圆圈数字就是尝试顺序；点「排除」的则永远不用。不点任何「优先」= 让 Cline 自己挑。
② 再选怎么用（右边的「严格钉住 / 优先+回退」）：只有在你勾了 2 个以上「优先」时这个选项才真正起作用。
这两种模式到底差在哪？（点开看）
严格钉住 —— 「必须用它」。假设你勾了 A、B：先只许用 A，Cline 绝对不能偷偷换成别家；A 出问题（报错、超时）时，本工具再单独发一次「只许用 B」的请求。「钉死 DeepSeek」就该用这个。
优先+回退 —— 「首选用它」。同样勾了 A、B：告诉 Cline「优先 A，不行就用 B」，剩下的交给 Cline 自己决定，所以可能少绕一圈、更不容易失败，但你没法保证最终是谁在服务。适合「能用就行，稳定第一」。
一句话：严格是「下命令」，优先+回退是「提建议」。想要确定的结果选严格，想要更高的成功率选优先+回退。
③ DeepSeek 用户请直接用默认值：deepseek-v4.1-flash-1017 这个模型已经帮你配好了「严格钉住 DeepSeek + 两项能力要求」。 两项要一起生效才管用（只配其中一项，请求仍可能被送去别家），所以别单独删掉其中一个；想恢复就点该行的「应用 DeepSeek 预设」。
有些客户端会自己指定想用哪家上游。选「以本页设置为准」时，本页的配置说了算，客户端的要求会被忽略；选「以客户端设置为准」时，客户端的优先，它没提的部分才用本页配置补上。不确定就用推荐的第一个。
